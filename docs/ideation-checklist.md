# アイデア出し用チェックリスト

元にしたのは Kagami の記録にあった dip 田中さんの記事（審査員・メンター視点） [ハッカソンでよく見る4つのパターン](https://zenn.dev/dip_techblog/articles/e2dcd745c3ba76) です。ハッカソンの審査員経験者の記事は、記録の中ではこの1本だけでした。

## 0. チームの目的（最初に1回だけ）

- 何のために参加するのかを、チームで一言にできている。たとえば「優勝を狙う」「動くものを最後まで出す」「〇〇という技術を試す」です。
- その一言をメンターに伝える準備ができている。伝えるとフィードバックの質が変わります。

## 1. 誰の、どんな瞬間の話か

- 使う人の「ある1日のある瞬間」を、時刻と場所つきで書ける。
- その瞬間に本人が感じていることを、本人の言葉で書ける。
- 背景から課題、課題から解決策を「だから」でつないで、声に出して説明できる。
- 背景の人とペルソナが同じ人になっている。
- 「若者」「モチベーション」「健康」のような大きな言葉で、つながっているように見せていない。
- 機能が「誰のどの瞬間」から出ている。連想ゲームで横に増やしていない。

## 2. その人はどうなっていたら嬉しいか

- 「誰が、どうなっていたら嬉しいか」を1文で書けている。
- 問題（理想と現状の差）と課題（その差を生んでいる原因にどう取り組むか）を分けて書けている。
- 問題をそのまま裏返した機能になっていない。たとえば「お金が足りない」から「支出を減らす機能」にする形です。
- 原因の候補をいくつか挙げて、自分たちがどれに取り組むのか選べている。

## 3. 既存のアプリとの違い

- 既存のアプリが平均的な困りごとをすでに解いている前提で、もっとニッチで具体的な場面に絞れている。
- その場面で既存のアプリがなぜ使われないのかを説明できる。

## 4. 自分たちが面白いと思うことから始める場合

- 「この瞬間が面白い」という具体的な場面が、感情と一緒に3つ挙げられる。
- 広げるなら「誰の何をよくするのか」を後から言えるようにしてある。炎上しそうな題材なら、誰の何のためにあるかを先に用意しておきます。

## 5. 提出前の最終確認

- 「なぜ参加したのか」「動機は何か」「この作品は誰の何をよくするのか」を、チーム全員が同じ言葉で言える。

記事はユーザーの困りごとからでも、「作りたい」からでも始めてよいという立場です。どちらから始めるかを先にチームで決めると、2と4のどちらを重く見るかが決まります。
