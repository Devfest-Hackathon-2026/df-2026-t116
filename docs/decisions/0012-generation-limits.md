# 0012 生成の打ち切りと回数上限

- 状態: 決定
- 日付: 2026-11-10（120秒は前提メモ追記 04:15 JST、設計書の修正は PR #19 のコミット ab2a78a）
- 決定者: 数値は設計書で AI が公式料金から計算して起案、@H4aruki が設計書の採用で決定（120秒は @H4aruki の決定として前提メモに明記）
- 関連: PR #19、#21、#25、[0002](0002-tech-stack.md)、[0005](0005-start-flow.md)、[0006](0006-generation-cost.md)、[0010](0010-gcp-billing-guards.md)

## 背景

- 画像生成を1回の HTTP 要求の中で待つ。待てる時間は App Hosting 5分、Firebase Hosting 経由 1分、Cloud Run 既定5分・最大60分（設計書 6節の出典）。
- 設計書の初版には打ち切り秒数の食い違い（50秒など）があり、Opus の PR #19 レビュー（2026-11-10 03:52）で must-fix になった。
- 費用: Vertex の spend cap ¥1,000（[0010](0010-gcp-billing-guards.md)）の内側に収める。1生成あたりの保守見積もり ≈ $0.045（画像出力 ≈ $0.034＋参照画像入力 ≈ $0.005＋Flash ≈ $0.005）。¥150/$ 仮定で ¥1,000 ≒ $6.67 → 生の上限 ≈ 148回。
- 旧「$20で約500本」はチームクレジット全体を画像だけに当てた計算で、根拠が弱かった（#25）。
- サーバーの最大数（`maxInstances: 3`）は同時に生成する数の上限ではないので、生成の数は回数で絞る必要がある。

## 検討した選択肢

### 打ち切り秒数
- 50秒: 画像生成に足りない恐れ。
- 120秒（採用）: プラットフォーム上限5分の内側で、利用者が待てる長さ。
- 5分いっぱい: 失敗のときに利用者を長く待たせる。

### 全体1日の回数
- 無制限: Vertex cap を超えやすい。
- 148回（生の上限）: 再試行・為替のぶれ・文章の増加で超える恐れ。
- 120回（採用）: 約 $5.4 ≒ ¥810 で余裕を残す。

## 決定

- `/api/nodes` の生成は **120秒で打ち切り**（`deadlineAt = 開始 + 120秒`）。期限切れの `generating` は画面では失敗として表示し、サーバーは次の書き込み経路で `failed` に更新する。完成の書き込みは「まだ generating かつ期限前」の条件付き。
- 回数: **1人1日10回**、**全体1日120回**（ページ生成。設定画も全体枠に1枚＝1回で数える方針は [0005](0005-start-flow.md)／[0006](0006-generation-cost.md)）。assist は1人1日5回（別枠）。
- 回数の確認と+1は、生成の前に1つのトランザクションで行い、AI の呼び出しはその外で行う。
- サーバー最大インスタンス 3（docs/11）。

## 理由（判断基準）

1. **待てる時間**: 120秒は App Hosting の5分の内側で、50秒より画像生成に余裕がある。
2. **費用**: 全体120回 ≈ ¥810 で Vertex cap ¥1,000 の内側。ただし月の cap は約148枚なので、実際は月の cap が先に効く（[0006](0006-generation-cost.md)）。
3. **公平**: 1人10回で、1人が全体枠を使い切らない。審査・デモには足りる（設計書 7節）。
4. **同時押し**: トランザクションで確かめて+1するので、同時に押されても上限を超えない。

## 却下した案と理由

| 案 | 理由 |
|---|---|
| 50秒打ち切り | 画像生成に足りない恐れ |
| 全体無制限 | Vertex cap を超えやすい |
| 旧「$20で約500本」 | 根拠が弱い（設計書で撤回） |
| 設定画を別枠で数える | cap を超えやすい（[0006](0006-generation-cost.md)） |

## 影響

- コード: `apphosting.yaml` の `LIMIT_PER_USER=10` / `LIMIT_GLOBAL=120` / `GEN_TIMEOUT_SEC=120` 環境変数と一致させる。回数は Firestore の `usage/{uid}_{日付}`・`usage/all_{日付}`。
- API: 上限を超えたら生成を断る。期限切れは `failed`。
- 運用: デモ前に回数を使い切らない。
- 費用: 1日最大 ≈ ¥810。月は Vertex cap ¥1,000 で頭打ち。

## リスクと対策

| リスク | 対策 |
|---|---|
| 120秒を超える生成が続く | 失敗として作り直せる。画像の試し（#38）で秒数を記録 |
| 期限後に古い結果が上書きする | 完成の書き込みを条件付きにする |
| 同時に押されて二重に数える | nodeId を画面が先に作り、同じ名前は作り直さない。回数と nodeId 作成を同一トランザクションに（#21） |
| 月の cap が先に尽きる | キャッシュ・リトライ上限（[0006](0006-generation-cost.md)） |

- 実際の生成秒数と1回あたりの実額を測ったら、120秒と120回を見直す。
