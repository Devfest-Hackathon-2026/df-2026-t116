## 検討した選択肢

### 案A: @H4aruki → Miso（チャット/Issue）→ Claude Code・Codex → PR、「標準」の制約（採用）
- 利点: 人が方針とマージを握り、実装は AI で速く回せる。PR と CI でレビューと検査が残る。
- 欠点: @H4aruki の確認待ちが入る。

### 案B: main へ直接コミット
- 利点: 速い。
- 欠点: レビューと CI を飛ばす。

### 案C: CloudAgent など別の実行環境へ AI が自分の判断で切り替える
- 欠点: トークン・権限の見通しが悪い（チーム方針）。

### AI によるマージの扱い
- 案1: AI は一切マージしない（従来の AGENTS.md の文面）。利点＝取り返しのつかない操作を人が必ず握る。欠点＝締切当日は人の確認待ちがボトルネックになり、CI 緑の PR が溜まる。実際の運用（11/10 の AI マージ）とも合わない。
- 案2: 人間が許可した場合のみ AI がマージしてよい（採用）。利点＝人が決める点は変わらず、許可を出した後の作業（main の取り込み・CI 確認・マージ）を AI のハーネスで回せる。欠点＝「許可」の範囲があいまいだと、許可されていない PR まで AI がマージするおそれ。
- 案3: CI が緑なら AI が自由にマージしてよい。利点＝最速。欠点＝人が方針を握らなくなる。CI は内容の良し悪し（仕様に合っているか）を見ない。

### 決定の残し方
- PR 本文だけ: PR を探さないと見つからない。
- ADR だけ: レビューの場で理由が読めない。
- ADR と PR 本文の両方に詳しく（採用）: 後から ADR で追え、レビュー時は PR で読める。

## 決定

- 流れ: **@H4aruki → Miso（チャット/Issue）→ Claude Code・Codex → PR**。
- PR/Issue はコードを読まなくても分かる形（画面変更は前後スクショ）。Issue / Project テンプレート、コミットメッセージ規約、ブランチ名規約を使う。
- リポジトリ制約は「標準」（main 直 push 禁止・PR・レビュー・CI・秘密検知。hooks）（[0004](0004-main-guardrails.md)）。
- Claude / Codex はサブスクリプションログイン経由。APIキー課金で回さない。CloudAgent に勝手に切り替えない。
- **AI によるマージは、人間（@H4aruki）が許可した場合のみ**してよい。許可が無い PR は AI がマージしない。許可された PR でも、CI が緑であることを確かめてから、確認とは別の操作でマージする。
- 今回（ハッカソン期間、締切 11/10 まで）は、人の確認待ちがボトルネックにならないよう、@H4aruki が許可を出し、AI のハーネス（レビュー・CI 確認・マージを回す仕組み）で回す（@H4aruki 2026-11-10 10:24 JST）。
- PR の向き先は常に main。積み重ね PR は使わない。1 Issue = 1 PR。
- **意思決定は `docs/decisions/` の ADR と PR 本文の両方に、なるべく詳しく書く**（背景・選択肢・理由・却下理由・影響・未決）。決定を含む PR は ADR を追加・更新し、PR 本文にも要約と理由を書く。過去の決定も ADR にする（2026-11-10、AGENTS.md に明記）。

## 理由（判断基準）

1. **人が方針とマージを握る**: 速さより取り返しのつかなさを避ける。マージの可否は人が決め、許可後の手作業だけを AI に任せる（案2）。締切当日に人をボトルネックにしない。
2. **コードを読まなくても分かる**: レビューする人がコードを読まなくても判断できる。
3. **費用**: 従量課金を出さない。
4. **後から追える**: 決定の背景と捨てた案が残っていれば、同じ議論をくり返さず、見直す条件も分かる。

## 却下した案と理由

| 案 | 理由 |
|---|---|
| main へ直接コミット | レビューと CI を飛ばす |
| CloudAgent への勝手な切替 | トークン・権限の見通しが悪い（チーム方針） |
| 積み重ね PR | #14 で変更が main に届かなかった |
| AI は一切マージしない | 締切当日は人の確認待ちがボトルネックになる。実際の運用とも合わない |
| CI が緑なら AI が自由にマージ | 人が方針を握らなくなる。CI は仕様に合っているかを見ない |
| 決定を PR 本文だけ／ADR だけに残す | どちらかだけでは、後から追うときかレビューのときに理由が読めない |

## 影響

- 運用: ブランチ名は `feat|fix|docs|chore/<issue>-…`。コミットは Conventional Commits（日本語可）。
- 運用: 同じリポジトリで AI を並列に動かすときは作業フォルダを分ける。結果の usage が0なら失敗扱い。
- 運用: 決定を含む PR は ADR の追加・更新が要る。PR テンプレートの「却下した代替案と理由」も埋める。
- 費用: Claude / Codex はサブスクの範囲。
