## 背景

- 最初の案D（[design-d-4koma.md](../design-d-4koma.md)）は「お題に続きを付け合い、同じ親を持つ続きの中で票が一番多い物が本筋」という木構造だった。単位は「起承転結で完結する4コマ」。
- #54（11/10 @Maaa2005）で訂正: 作るのは**普通の漫画（ストーリー漫画）をみんなで続けて描いていく物**。1人が足す一番小さい単位は「4コマ分の1枚＝漫画の1ページ」で、話はページをまたいで続く。起承転結はやめ、投票の理由は「オチが良い」→「続きが気になる」。
- さらに @Maaa2005 が「1話＝4ページ・スワイプ評価・漫画アプリ画面」の連載形を設計し、#60（サーバー）・#56（Vertex 生成）・#61（画面）で実装した。
- 06:33 JST 時点では、#56・#60・#61 は「連載・スワイプ評価・キャラ刷新の設計変更」なので @H4aruki の確認待ちで保留していた（main との衝突解消と、3本を合わせた lint・テスト79件・build は緑）。
- 09:38 JST に @H4aruki が連載形式を OK し、#60 → #56 → #61 の順にマージした。

## 検討した選択肢

### 案A: 連載形式（1話＝4ページ、募集中のページは常に1つ、スワイプ評価）（採用）
- 利点: 漫画アプリと同じ読み方ができる。決まったページは変わらず、完結した話を1話から読める。評価が1タップで軽い。
- 欠点: サーバーの作り直しが要る（ページの締め、山の配り方）。候補が集まらないとページが決まらない（→ 時間で決める条件を入れた）。

### 案B: 分岐を無限に増やす木（最初の案D）
- 利点: 実装がすでにあった。誰でもどこにでも続きを付けられる。
- 欠点: 本筋が票で入れ替わり続け、読む体験が漫画アプリから遠い。

### 案C: 起承転結で完結する1本の4コマを付け合う
- 利点: 1本ごとに完結し、評価しやすい。
- 欠点: @Maaa2005 の意図（ストーリー漫画を続けて描く）と違う（#54 で訂正）。

## 決定

- **みんなで描く連載漫画**とする。1話＝4ページ、1ページ＝4コマ。1人が描くのは1ページ（4コマのセリフ）。募集中のページは常に1つ。スワイプで評価し、一番人気がそのページに決まる。4ページ目が決まるとその話が完結し、次の話の1ページ目の募集が始まる。
- 決まったページは変わらない。完結した話は1話目から全部読める。
- 画面は漫画アプリ風（ホーム／作品／読む／評価する／描く／作品を始める）。手本は LINE マンガ・ピッコマ・ジャンプ+。
- 作品を始める人が大枠（物語の軸・絵柄・キャラ）を決める（@Maaa2005）。始め方の細部は [0005](0005-start-flow.md)。
- AI が決めた主な細部（理由は設計書（2））:
  - ページが決まる条件: ①完成した候補が2本以上で最初の完成から5分 ②1本だけでも30分 ③始めた人の「締めて決める」（候補1本以上）。
  - 勝ち: いいねの数 → いいねの割合 → 早く描いた方 → id。
  - 他人の候補の票数は自分がスワイプするまで見せない。カードの順は人ごとにばらばら。
  - 1つのページに1人1本。
- 設計書（2）が画面・データの正。生成と課金の骨格は設計書（1）。

## 理由（判断基準）

1. **作りたい物との一致**: @Maaa2005 の意図（ストーリー漫画を続けて描く）に合う（#54）。
2. **読む体験**: 漫画アプリと同じく、決まったページを順に読める（案B は本筋が入れ替わり続ける）。
3. **評価の軽さ**: スワイプで1タップ。理由は後から任意（NN/G の指針）。
4. **偏りを減らす**: 票数を先に見せない（Salganik 2006）、カード順をばらばらに。
5. **締切の日に部品を増やさない**: ページの締めは定期実行を足さず、読む・描く・評価する時に条件を見てその場で1つのトランザクションで決める（PR #60）。

## 却下した案と理由

| 案 | 理由 |
|---|---|
| 起承転結で完結する1本の4コマ | #54 でストーリー漫画の1ページ単位に訂正 |
| 分岐を無限に増やす木だけ | 読む体験が漫画アプリから遠くなる（連載形を採用） |
| 時計の仕組み（定期実行）でページを締める | 部品が増える（PR #60） |
| Firestore の複合インデックスで山を引く | 設定と待ち時間が増える。等号だけの問い合わせにし、並べ替えはサーバーで行う（PR #60） |
| 票数をいつも見せる | 偏りが増す（Salganik 2006） |

## リスクと対策

| リスク | 対策 |
