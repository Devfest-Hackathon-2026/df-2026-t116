# 判断記録（ADR）

後から「なぜそうしたか」「何を捨てたか」を追えるように、決めたことを**なるべく詳しく**残す（2026-11-10 @H4aruki のルール。[AGENTS.md](../../AGENTS.md) の「意思決定の記録」）。

- ファイル名: `NNNN-短い名前.md`（例: `0001-submission-transfer.md`）
- 決定を含む PR は、ADR を追加・更新し、**PR 本文にも要約と理由**を書く（ADR だけ・PR だけにしない）。
- 決定内容を変えたときは、古い ADR を消さずに「状態」を更新し、新しい ADR か追記で経緯を残す。
- 秘密情報（鍵・トークン・パスワード・請求先アカウントID・個人メール）は書かない。GCP のプロジェクトIDは既存 docs と同じ範囲なら書いてよい。
- 出典に無い事実は作らない。分からないことは「未確認」と書く。

## テンプレート

```md
# NNNN 題

- 状態: 決定 / 未決 / 置き換え（→ NNNN）
- 日付: YYYY-MM-DD（時刻が分かれば HH:MM JST）
- 決定者: 誰が決めたか（AI が起案した部分は分けて書く）
- 関連: Issue / PR / 他の ADR

## 背景
なぜ決める必要があったか。制約（締切・費用・規約・技術）と、判断に使った数値。

## 検討した選択肢
### 案A: …
- 利点:
- 欠点:
### 案B: …

## 決定
何をどうするか。数値・名前・範囲を具体的に。

## 理由（判断基準）
どの基準で選んだか（例: 費用、締切、安全、独創性）と、各案がそれをどう満たすか。

## 却下した案と理由
| 案 | 採らなかった理由 |

## 影響
- コード:
- API・データ:
- 運用:
- 費用:

## リスクと対策
| リスク | 対策 |

## 未決事項・見直す条件
まだ決まっていないこと。どうなったらこの決定を見直すか。

## 出典
前提メモの日時、Issue・PR 番号、ファイル、URL。
```

Issue フォーム `decision` との対応:

| ADR の項目 | Issue フォームの項目 |
|---|---|
| 背景 | 今の状態、この決定が止めているもの |
| 検討した選択肢・却下した案と理由 | 選択肢と、採らなかった案の理由 |
| 決定・理由 | 決定（決定後に埋める） |
| 影響・リスク・未決 | 決定欄に書く |
