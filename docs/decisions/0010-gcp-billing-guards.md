# 0010 GCPの予算・支出上限とカード請求を出さない

- 状態: 決定
- 日付: 2026-11-04〜2026-11-10（方針 11-04 21:45、仕組みの作成 11-04 21:50〜22:00、設定時期の決定 11-09 15:12、#31 で設定済みを確認 11-10 06:05、いずれも JST）
- 決定者: @H4aruki。kill switch の仕組みは Miso の依頼で AI が作成
- 関連: #31、[docs/11](../11-gcp-deploy.md)、[0002](0002-tech-stack.md)、[0006](0006-generation-cost.md)

## 背景

- GCP は @H4aruki のアカウントと配布クレジットで使う。請求設定は @H4aruki が手動で行う（クレジットは1回限り）（2026-11-04 21:01）。
- 大会クレジットは1チーム $20（キックオフ資料スライド11）。有効化にはカード登録が必要で、Google AI Studio には使えない（2026-11-04 21:45）。2026-11-10 時点のクレジット残は ¥3,165（〜2027-05-05）。
- 予算アラートは通知だけで、自動では止まらない（キックオフ資料 p40）。
- 運営の追加連絡（2026-11-09 15:06）: GCP は費用上限の設定が必須。API キー・JSON キーを GitHub に上げない。高額請求は運営免責。
- 画像の AI には無料枠が無い（設計書 7節）。

## 検討した選択肢

### 案A: 予算（通知）＋ kill switch 用予算 ＋ サービスごとの spend cap（採用）
- 利点: 通知・自動停止・サービス単位の上限の3層で守れる。運営の必須条件を満たす。
- 欠点: kill switch が動くと請求先のリンクが外れ、本番が止まる。spend cap の合計（¥4,000）はクレジット残より大きい。

### 案B: 予算の通知だけ
- 利点: 設定が簡単。
- 欠点: 自動では止まらない。

### 案C: 従量のまま様子を見る
- 利点: 何もしなくてよい。
- 欠点: 高額請求のリスク。運営は免責。

## 決定

- 使うサービスごとに **spend cap** を付ける（Cloud Run／Cloud Run functions／Gemini API／Vertex AI 各¥1,000）。
- プロジェクト予算 **¥3,000**（通知、50/90/100% と予測 100%、クレジットを除いて計測）と、Pub/Sub 連携の **kill switch 用予算¥3,000**（予算 → Pub/Sub → Cloud Run function `billing-guard` が請求先のリンクを外す）。
- 最初のデプロイ／最初の Gemini（Vertex）呼び出しより前に設定する（それまでデプロイしない）。
- AI Studio の APIキー経路は使わず Vertex＋ADC（鍵の詳細は [0002](0002-tech-stack.md)）。
- 上限の数値変更は [0006](0006-generation-cost.md) のとおり、安易に Vertex へ寄せない。
- 請求先のリンクを外せなくなる設定（組織ポリシーや権限のロック）はしない（kill switch が効かなくなるため、docs/11）。

## 理由（判断基準）

1. **カード請求を絶対に出さない**（@H4aruki）: 通知だけでは止まらないので、自動停止とサービス単位の上限が要る。
2. **運営の必須条件**: 費用上限の設定（2026-11-09）。
3. **順番**: 上限を付けてから使い始める。後から付けると、その間に請求が出うる。

## 却下した案と理由

| 案 | 理由 |
|---|---|
| 予算通知だけ | 自動停止しない |
| 従量のまま様子見 | 高額請求リスク。運営は免責と案内あり |
| AI Studio の API キー | クレジットが使えない。鍵の管理が要る |

## 影響

- コード: なし（GCP 側の設定）。アプリ側の回数上限（[0012](0012-generation-limits.md)）は別に持つ。
- 運用: 実装・運用は docs/11 に従う。kill switch のコードは開発用リポジトリの外（AI エージェントの作業環境）にある。
- 費用: Vertex は月 ¥1,000 が上限（約140〜150枚、[0006](0006-generation-cost.md)）。
- 請求先アカウントIDや個人メールはリポに書かない。クレジット残額の最新値はコンソールが正（文書の数字は時点付き）。

## リスクと対策

| リスク | 対策 |
|---|---|
| kill switch が動いて本番が止まる（デプロイ URL は 11/14 まで動かす必要がある） | ¥3,000 に届かないよう、アプリの回数上限と spend cap で先に止める |
| spend cap の合計（¥4,000）がクレジット残（¥3,165）を超える | 実際に使うのは Vertex と Cloud Run が中心。cap は上げない（[0006](0006-generation-cost.md)） |
| gcloud ではクレジット残高とカードの有無が見られない | コンソールで本人が確認する |
| 予算・cap の通知が遅れて届く | 金額に余裕を持たせた上限にしている |
