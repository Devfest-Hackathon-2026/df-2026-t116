# 0005 作品の始め方とキャラ（パーツ選択）

- 状態: 決定（設計のみ。実装は本 ADR を含む PR のマージ後〜Demo Day）
- 日付: 2026-11-10（初案 09:21 JST、確定 09:55 JST、描き直しの失敗回の扱い 10:45 JST）
- 決定者: Haruki さん。安全の案出しは Miso の調査（`0004-safety-cost.md`）と Opus のレビュー（`0002-opus-review.md`）。画面・API の細部は AI が起案し [design-d-serial.md](../design-d-serial.md) に記載
- 関連: #58、PR #63、[0006](0006-generation-cost.md)、[0008](0008-serial-format.md)、[0009](0009-human-story-ai-art.md)

## 背景

- 連載形式（[0008](0008-serial-format.md)）では、作品を始める人が大枠（物語の軸・絵柄・キャラ）を決める（中村さん）。それまでのキャラは用意済みの固定4体（ミカン・テツ・キナコ・ハカセ）から選ぶだけだった。
- Haruki さんの問題提起（11/10）: 「こちらでキャラクターを指定すると独創性に欠ける、自由に作成させると著作権の問題がある、ただ自由に作成はさせたい」。
- 著作権の考え方: 文化庁「AIと著作権に関する考え方」（令和6年3月15日）では、生成・利用段階の侵害は従来どおり**類似性＋依拠性**で判断する。利用者が既存作品を認識して固有名詞等を入力すると依拠性が認められやすい。侵害が頻発し事業者が放置すると事業者も責任主体になり得る（法的拘束力はない）。
- Google の生成AI補償は、意図的な侵害やフィルタ回避などを除外する。Vertex の画像安全フィルタは、漫画の既存キャラ模倣を完全に防ぐとは書かれていない（`0004-safety-cost.md`）。
- 既存の実装の文チェックは、実在人名と他作品のキャラ**名**だけを拒否していた。名前を出さずに見た目の特徴を並べる模倣は未対策だった。
- 提出物に著作物利用シートがある（キックオフ資料 p37・p48）。
- 作品名で人が集まる一方、開始時に必須にすると始めのハードルが上がる。
- 09:21 の初案は「キャラ設定＝自由記入＋AI案」「作品名＝自由記入＋AI案、好きなときに決める（開始時は無題可）」だった。上の著作権の懸念を受けて 09:55 に見直した。
- 締切: 今日（11/10）18:00 のコード停止には間に合わないため、設計の PR だけを先に出し、実装は Demo Day（11/27）まで（Opus 判断）。

## 検討した選択肢（キャラの作り方）

### 案A: 大きなパーツ選択＋短い自由記入（採用）
- 利点: 組み合わせの数が大きく「自分のキャラ」感が残る。既存キャラ名の入力という依拠性の入口を構造的に狭められる（文化庁のいう「一定の措置」として説明しやすい）。UI はセレクト中心で実装が軽い。著作物利用シートに「パーツはオリジナルの選択肢、生成は Vertex」と書ける。
- 欠点: 細部の自由度は下がる。小さなパーツ（目の形など）は画像AIが確実に反映するとは限らない。

### 案B: 見た目の完全自由記入＋多層ガード（入力チェック・生成フィルタ・通報・規約で投稿者責任）
- 利点: 独創性が最大。Haruki さんの「自由に作らせたい」に最も近い。
- 欠点: 著作権リスクが最大。規約で投稿者責任にしても事業者責任は消えない。意図的模倣は Google 補償の対象外。チェック強化と通報 UI が要り、Demo Day までに全部は重い。

### 案C: 用意済みキャラだけ（固定4体）、独創性は物語の軸・セリフで出す
- 利点: 著作権リスクが最小。追加実装が要らない。
- 欠点: Haruki さんの「独創性に欠ける」という懸念そのもの。

### パーツの粒度
- 大きなパーツだけ（髪型・髪色・体型・服の種類・服の色・年齢の印象・種族など、絵でわかるもの）: 画像AIに反映されやすい。
- 細かなパーツまで: 反映が不確実で、選んだのに絵に出ないと不満になる。Haruki さんの質問（「選択したパーツを確実にキャラクターに反映させれるの？」）を受け、大きなパーツだけに絞った。細部は短い自由記入で「反映されればよい」扱い。

## 決定

- **物語の軸**: 自由記入（1〜200字）。AI案は出さない。
- **絵柄**: 6つの選択肢（明るいカラー・少年漫画・少女漫画・劇画・ゆるかわ・モノクロ）。
- **キャラ（1〜2体）**: **大きなパーツだけ選択**＋**短い自由記入**（名前1〜20字・自由記入0〜80字）。サーバーがパーツから見た目文を組み立てる。完全な自由記入はやらない。確定後は見た目の編集なし。
- **例から選ぶ**: 既存固定4体を残し、パーツ選択の代わりに使える。
- **作品名**: 開始時は未設定可（保存は空文字にせずフィールド無し、画面だけ「無題」）。始めた人が好きなときに付ける（`PATCH /api/themes/[id]`、1〜20字、文チェック付き）。
- **設定画**: 開始後に画像AIが1体1枚作る → **始めた人が確認して確定**。描き直しは **1作品2回まで**。全体1日120回の枠に1枚＝1回で数える。確定画を毎ページの参照画像に渡す。揃い・確認前は1ページ目を描けない（`POST /api/nodes` は 409）。
- **描き直しの失敗回（Haruki さん 2026-11-10 10:45 JST）**: 描き直しを押して、対象の設定画が1枚もできなかった回（生成器のエラー・安全フィルタでの拒否・時間切れ・画像の保存失敗）は、**2回の描き直し回数に数えない**。1枚でもできた回は1回と数える。一方で、**試行そのものは全体の日次上限（1日120回、[0012](0012-generation-limits.md)）に描く枚数ぶん数え、失敗しても戻さない**。同時押しで2回を超えないよう、押した時点のトランザクションで回数を +1 で予約し、全部失敗なら生成後のトランザクションで -1 して戻す。設定画は今どおり1人1日10回（ページ生成の枠）には数えない。
- **文チェック**: 物語の軸・キャラ名と短い自由記入・作品名（POST／PATCH）を文章AIで確かめ、不適切・実在の人・他作品名・**既存キャラを想起させる文**を拒む。画像の指示にも「既存作品に似せない」を入れる。管理者が問題のある作品を非表示にできる余地を残す。
- **AIの役割**: 話（軸・セリフ）は人。AIは絵と、押したときだけの下書き（キャラ案＝余裕があれば、作品名案＝後回し）。画像アップロードはやらない。
- **実装の優先**: 必須＝作品名任意＋PATCH／パーツ選択キャラ＋文チェック／設定画生成＋確認（描き直し2回）。余裕＝キャラ案の下書き。後回し＝作品名のAI案。やらない＝物語の軸のAI補助・画像アップロード・完全自由記入の見た目文。
- 詳細の正本は [design-d-serial.md](../design-d-serial.md)。費用の守りは [0006](0006-generation-cost.md)。

## 理由（判断基準）

1. **独創性と著作権の両立**（Haruki さんの問題提起）: 案A は組み合わせで独創性を残しつつ、依拠性の入口を狭める。案B は著作権、案C は独創性を満たさない。Opus も A を推奨（A > C > B）。
2. **反映の確実さ**: 大きなパーツだけにすれば、選んだものが絵に出やすい。
3. **始めやすさ**: 作品名は後からでよい。例4体からも始められる。
4. **品質と権利の目視**: 設定画は人が見て確定する。自動確定だと誰も見ない。
5. **費用**: 描き直しを2回に絞り、全体枠で数えて Vertex の上限を食い潰さない（[0006](0006-generation-cost.md)）。
6. 例4体を残すのは Haruki さんの選択（「既存のキャラ4体は例として残す」）。

## 却下した案と理由

| 案 | 理由 |
|---|---|
| 用意済みキャラのみ | 独創性に欠ける（Haruki） |
| 見た目の完全自由記入 | 依拠性の入口が広い。規約だけでは事業者責任は消えない（0004・Opus） |
| 細かなパーツまで選択 | 画像AIに確実に反映できない |
| キャラ設定の自由記入＋AI案（09:21 初案） | 著作権の懸念で 09:55 にパーツ選択へ変更 |
| 開始時に作品名必須 | 始めのハードルが上がる |
| 設定画を確認なしで自動確定 | 品質と権利リスクの目視が無い |
| 描き直し無制限 | Vertex 回数を食い潰す |
| 失敗した回も描き直し2回に数える（10:45 以前の実装） | 始めた人のせいでない失敗（安全フィルタの誤判定・時間切れ）で回数を失い、作品を始められなくなる |
| 失敗した回は日次上限からも戻す | 失敗を何度でも無料で再試行でき、上限が効かない。安全フィルタで止まった応答は課金され得る（下の出典）ので、費用の見積りからも外れる |
| 失敗の種類で分ける（4xx/5xx だけ戻す等） | 今の生成器の戻り値では種類を確実に見分けられない。時間切れはサーバー側で生成が終わって課金されている可能性がある。18:00 のコードストップまでに確かめきれない |
| 画像アップロード | 実在の人の写真や既存作品の画像が入る |

## 影響

- コード: `src/lib/characters.ts` の固定4体は「例」として残す。パーツの選択肢の定義と、パーツから見た目文を組み立てる処理を足す。文チェックのプロンプトに「既存キャラを想起させる組み合わせ」を足す。
- API・データ: `POST /api/themes` の `characters` は例idまたは `{ name, parts, note? }`、`title` は任意。新しい入口 `PATCH /api/themes/[id]`、`POST /api/themes/[id]/sheets/confirm`、`POST /api/themes/[id]/sheets/retry`、`POST /api/themes/assist`（1人1日5回）。`themes` に `title`（未設定可）・`characters`（`sheetPath`・`sheetStatus`・`sheetRetries`）を足す。
- 画面: `/new` にパーツ選択、`/t/[id]` に設定画の確認・描き直し（残り回数）と作品名の付け直し。無題のときはホームの棚とカードに軸の冒頭か始めた人を添える。
- 運用: 著作物利用シートに、パーツはオリジナルの選択肢・生成は Vertex、と書ける。
- 費用: 設定画は1作品あたり1〜2枚＋描き直し最大2回。全体1日120回の枠の中で数える。

## リスクと対策

| リスク | 対策 |
|---|---|
| パーツの組み合わせでも既存キャラに似る | 文チェックで想起を拒否、画像の指示に「似せない」、始めた人が確認して描き直し、管理者が非表示 |
| 短い自由記入で既存キャラを指す | 字数を80字に絞り、文チェックの対象にする |
| 設定画の生成が失敗して作品を始められない | 描き直し（2回まで）。1枚もできなかった回は2回に数えない（10:45 決定） |
| 失敗が続くと全体の日次上限（120）を食う | 失敗の無限の再試行を防ぐため、あえて上限に数える。上限に達したら 429。翌日に戻る |
| 実装が Demo Day に間に合わない | 優先順（必須・余裕・後回し）で削る。例4体からも始められる |
