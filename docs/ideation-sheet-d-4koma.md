## 1. 誰の、どんな瞬間か
- 誰：話を考えるのは好きだが、絵は描けない高校生・大学生
- いつ・どこで：夜23時ごろ、寝る前に布団の中でSNSを見ているとき
- そのとき起きていること：面白い展開を思いつくが、絵が描けないので文章で一言つぶやくだけ。誰にも拾われずに流れていく
- 本人の心の声：「この続き、漫画で見たいのに描けない」
- その後どうなるか：思いつきはその夜で消える。続きを一緒に考えてくれる相手もいない
- [DevFest 3-a] この瞬間を見せれば、課題が具体的で明確だと伝わるか：□ はい（【チームで】確認）

## 2. 理想と問題と課題
- 理想（1文）：絵が描けない人も、思いついた話をみんなに漫画で読んでもらい、続きを一緒に作れている状態
- 現状：漫画で見せるには絵の力と時間が要る。AIに丸ごと作らせると「AIのゴミ」と言われ、人の作品として見てもらえない
- 問題（理想と現状の差）：話を考える力はあるのに、漫画として出して読んでもらう手段がない
- 原因の候補：① 絵を描く技術と時間がない　② 1人で最後まで話を作り切るのが重い　③ AIが中身まで作ると、人の作品と見てもらえない
- 取り組む原因と理由：①と③。なぜなら、①はAIに絵だけ任せれば消せる。そのとき③を避けるには「話は人が書く」を仕組みで守る必要がある。②は続きをみんなで付け合う形で軽くなる
- 課題（その原因にどう取り組むか）：人が書いた続きだけをAIが4コマにする。評価は「なぜ良いか」で返し、人が作った物として読まれる場にする
- [DevFest 3] この課題は社会課題として言えるか：表現したい物はあるのに表現の手段を持たない人たちに共通する「出す場がない」。加えて、AIの作品があふれ人の創作が埋もれる問題（OpenAI の動画SNS「Sora」は2026年4月に終了、Meta の Vibes は「AIのゴミ」と批判された）

## 3. 解決策
- 解決策：お題に続きを文章で付け合い、AIが4コマ漫画にし、みんなの「なぜ良いか」投票で本筋が決まっていく場
- 「だから」でつなぐと：
  AIの作品があふれ、人の創作が埋もれているという背景がある。だから寝る前に思いついた話が、絵が描けずに消える瞬間が起きる。
  だから、話は人が書き、絵だけをAIに任せて漫画にできる事が課題。だから、お題に続きを付け合うと4コマになる場を作る。
- MVPで最初に動かす1機能：お題に続きを1〜4行書くと、同じキャラの4コマ漫画が出る
- やらないこと（横に広げない機能）：動画にする／作者への点をお金に換える／コメント欄／ロブロックスのアバターや名前（規約で漫画や出版物への利用が禁じられている）／実在の人の顔
- [DevFest 3-b] この仕組みで、2で選んだ原因が実際に減る理由：①は絵をAIが描くので、絵の技術と時間が要らなくなる。③は話の欄に人が書いた文しか入らず、AIは絵と吹き出しの配置しか作らないので、作品の中身は人の物のまま残る
- [DevFest 2-a] デモで通しで動かす流れ：① 誰かがお題を出す → ② 2人が続きを書き、それぞれ4コマになる → ③ 理由つき投票で片方が本筋になり、その先にまた続きが付けられる
- [DevFest 2-b] 1の人が迷わず目的を達成できる画面か：□ はい（迷いそうな箇所：キャラの見た目をどこで決めるか。お題を出す人が最初に決める案）

## 4. 既存のアプリとの違い
- 似ている既存のアプリ：4コマ部（4コマを描いて見せ合うアプリ）、GENSEKI の続き募集（前半2コマを用意して後半を募るコンテスト）、Sora・Meta Vibes（AIが動画を作って投稿し合うSNS）、Fable Showrunner（AIで番組の回を作る）
- その場面でそれが使われない理由：4コマ部は自分で絵を描く必要がある。GENSEKI は期間限定のコンテストで、続きのさらに先がない。Sora や Vibes はAIが中身まで作るので、人の作品として読まれない
- 私たちだけが解く問い：「絵をAIに任せつつ、作品を人の物のままにするにはどうするか」

## 5. 面白さ（作りたいものから始めた場合）
- 面白い瞬間①：自分が書いた1行が、その場で4コマ漫画になる → 感情：驚き・うれしさ
- 面白い瞬間②：他の人の続きで、思ってもみない展開になる → 感情：笑い
- 面白い瞬間③：自分の続きが投票で本筋に選ばれ、「オチが良い」の理由が並ぶ → 感情：誇らしさ
- 誰の何をよくするか：話を考えるのが好きでも絵が描けない人が、自分の話を漫画で読んでもらえるようにする
  （DevFest は「社会課題への解決力」が24点中6点あるので、ここは後回しにせず最初に埋める）

## 6. Google 技術（解決策が決まってから）
- 中核で使う Google 技術：Gemini の画像生成（Nano Banana 2.1）で4コマの絵を作る。Gemini（文章）で、続きの文を4つの場面に割り振り、似すぎ・不適切な内容を確かめる
- [DevFest 1-a] それを外すと作品が成り立たない理由：絵が描けない人の文を漫画にする部分そのものなので、外すと「文章を投稿し合うだけ」になる
- [DevFest 1-b] それを選んだ理由：参照画像で同じ人物を最大4人まで描き分けられ、4コマで同じキャラを保てる。日本語の文字を描くのが得意な言語に入っており、吹き出しに使える。4コマを縦長の1枚で作るので1本約0.034ドル（約5円）、20ドルで約500本作れる
  選ばなかった案：Gemini Omni 1.2 Flash で動画にする（選ばなかった理由：15秒で約1ドルと高く、日本語のセリフは公式に未評価）／Imagen 4（選ばなかった理由：安いが、同じキャラを参照画像で描き分けられる事を今回確かめたのは Nano Banana 側だけ）
- 実行基盤：□ Cloud Run　□ App Engine　■ Firebase App Hosting　□ Firebase Hosting　□ GKE　□ Compute Engine
  （Next.js を Firebase App Hosting に置く。中身は Cloud Run で動く。データは Firestore、ログインは Firebase Auth。詳しくは [設計書](design-d-4koma.md)。最終は decisions/0002 で【チームで】決定）
- [DevFest 2-c] 安全性と保守性への配慮（鍵の扱い・権限・構成）：鍵は Secret Manager に置き、画像の生成はサーバー側からだけ呼ぶ。Cloud Run は同時に動く数の上限を絞り、予算の通知を置く。1人1日の生成回数に上限を付ける
