# 10. CI とフックの仕組み

規約（Conventional Commits、ブランチ名）を、ローカルのフックと GitHub Actions の二段で守る。

## ローカルフック（`.githooks/`）

有効化: `bash scripts/setup-hooks.sh`（何度実行しても同じ）。

| フック | 内容 |
|---|---|
| `commit-msg` | `scripts/check-commit-msg.sh` で 1 行目を検査。Merge / `Revert "..."` / fixup! / squash! は通す |
| `pre-commit` | main への直接コミットを止める。`.env`（`.env.example` は除く）、`*.pem`、`*.key`、`id_rsa`、`credentials.json` のステージを止める。gitleaks があれば `gitleaks git --staged --redact --verbose`（古い版は `gitleaks protect --staged --redact`）で検査。無ければ黄色の警告を出してスキップ |

| `pre-push` | stdin の各行（local_ref local_sha remote_ref remote_sha）を検査する。`refs/heads/main` への push と main の削除を止める。remote_sha が local_sha の祖先でない更新（非 fast-forward = force push）を全ブランチで止める。新規・更新ブランチの名前を `scripts/check-branch-name.sh` で検査する。ブランチ削除（main 以外）は通す。メッセージには対処方法が付く |

ブランチ名は `scripts/check-branch-name.sh <名前>` で確認できる。形式は `<type>/<Issue番号>-<小文字英数とハイフン>`。main は使えない。

## Claude Code フック（`.claude/`）

`.claude/settings.json` の PreToolUse（matcher `Bash`）が `.claude/hooks/guard-git.sh` を呼ぶ。stdin の JSON の `tool_input.command` を `jq`（無ければ `python3`）で取り出し、次のものは exit 2 と理由・対処を stderr に出してブロックする。それ以外は exit 0。

- `git push` で main / `HEAD:main` を対象にするもの
- `--force` / `-f` / `--force-with-lease` / `+refspec`
- `--delete main` / `:main`
- あらゆる git コマンドの `--no-verify`
- `git config core.hooksPath` の変更（`-c core.hooksPath=...` を含む。フックの設定は `scripts/setup-hooks.sh` で行う）

`&&` `;` `|` で区切った各コマンドを見る。文字列の照合による簡易判定なので、守りの一層として使う。

## Claude 以外のツール（Cursor / Codex / Grok Build）

判定は共通の `scripts/guard-git-command.sh`（上の Claude Code と同じ対象）。各ツールの `guard-git.sh` は入力 JSON からコマンドを取り出し、共通スクリプトを呼んで、ツール形式で応答する薄いアダプタ。テストは `scripts/test-guard-git.sh`（`test-conventions.sh` から呼ぶ）。

| ツール | 設定 | 止まる仕組み | 止まらない穴 |
|---|---|---|---|
| Claude Code | `.claude/settings.json` | PreToolUse、exit 2 | 文字列照合の簡易判定 |
| Cursor | `.cursor/hooks.json` | `beforeShellExecution`、`permission: deny`、`failClosed: true` | trusted workspace でないと hooks が動かない |
| Codex | `.codex/hooks.json` | PreToolUse（`Bash`）、`permissionDecision: deny` | プロジェクトを trust し、`/hooks` でフック定義を review & trust するまでスキップされる。フックの error / timeout / 不正出力は fail-open（止まらない） |
| Grok Build | `.grok/hooks/guard-git.json` | PreToolUse（`Bash`）、`decision: deny` | 初回は `/hooks-trust` または `grok --trust` が必要。失敗・timeout・不正出力は fail-open |

どのツールでも、フックを信頼する前や、フックが落ちたときは止まらない。最後の砦は引き続き `.githooks` と CI。

## 守りの層

| 層 | 役割 |
|---|---|
| GitHub ブランチ保護（使えれば） | main への直接 push・force push・削除を GitHub 側で拒否する。private リポジトリの Free プランでは使えないことがある |
| git フック（`.githooks/`） | commit 時と push 時にローカルで止める |
| ツール別フック（`.claude/` `.cursor/` `.codex/` `.grok/`） | Claude Code / Cursor / Codex / Grok が実行する前に危険な git コマンドを止める（信頼設定が必要なものがある） |
| CI（PR で実行） | 規約・テスト・秘密情報を PR で検査する |

どの層も単独では抜け道がある。層を重ねて使う。

## CI（`.github/workflows/ci.yml`）

トリガーは pull_request と main への push。古い実行は concurrency で取り消す。各ジョブは timeout 5 分、既定の権限は `contents: read`。

| ジョブ | 内容 |
|---|---|
| `lint-test` | 全 `.sh` と `.githooks/*` を `bash -n`、shellcheck（runner にあれば）、`package.json` があれば `npm ci && npm run lint --if-present && npm test --if-present`（無ければ「アプリ未作成。スキップ」で成功。runner の node を使う）、`scripts/test-conventions.sh` |
| `conventions`（PR のみ） | PR タイトル、head ブランチ名、base..head の各コミットメッセージを検査。値は env 経由で渡す（スクリプトインジェクション対策） |
| `secret-scan` | gitleaks CLI（v8.30.1 をピン、GitHub Releases のチェックサムで検証）を直接実行。PR は `base..head`、push は `before..after`（新規ブランチなど before が 0 の場合は全履歴）を `gitleaks git --redact --verbose --exit-code 1` で検査。漏れがあれば非ゼロで失敗。権限は `contents: read` のみ |

checkout は SHA 固定。

## Actions の分数

private リポジトリでは Actions の分数を消費する。Free は 2,000 分/月、Pro は 3,000 分/月。1 回の実行はジョブ 3 本で、概算 3〜6 分（ジョブごとに切り上げ）。1 日 20 回動かすと月 1,800〜3,600 分になりうるので、Free では超えることがある。public リポジトリは無料。

## gitleaks のライセンス

Org では gitleaks-action にライセンスが要るため、CLI をピンして CI で直接走らせる。`gitleaks/gitleaks-action` は使わないので `GITLEAKS_LICENSE` は不要。CLI はキーなしで動く。

## 運用ルール

- gitleaks v8.30.1 は bot ボックスの `/usr/local/bin/gitleaks` に導入済み（公式 GitHub リリース、SHA256 検証済み、2026-11-04）。そのマシンでは pre-commit フックがローカルでスキャンする。未導入のマシンでは従来どおり警告が出て、スキャンは CI だけになる。
- `--no-verify` は使わない。フックで止まったら原因を直す。
