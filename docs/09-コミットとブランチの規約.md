# コミットとブランチの規約

## コミット（Conventional Commits）

形式: `<type>(<scope>): <説明>`。scope は任意。説明は日本語でよい。

| type | 使いどころ |
|---|---|
| feat | 機能の追加 |
| fix | 不具合の修正 |
| docs | ドキュメントだけの変更 |
| style | 動作に影響しない整形 |
| refactor | 動作を変えない書き換え |
| test | テストの追加・修正 |
| chore | 雑務（設定、依存の更新など） |
| ci | CI の設定 |
| perf | 性能の改善 |
| build | ビルドまわり |
| revert | 取り消し |

例:

- `feat: 症状入力から受診科の候補を3件返す`
- `feat(result): 候補0件のときの案内を追加`
- `fix(input): 空文字で送信するとエラーになる問題を修正`
- `docs: コードフリーズを19:00に確定`
- `ci: 秘密情報の検査を追加`
- `revert: 結果画面の並び替えを元に戻す`

**PR タイトルも同じ形式**にする。

## ブランチ

形式: `<type>/<Issue番号>-<短い英小文字ハイフン>`

例: `feat/123-login-form`、`fix/45-empty-input`、`docs/8-projects-guide`

- **main への直接 push は禁止**。必ずブランチから PR を出す
- 1 ブランチ = 1 Issue = 1 PR

## hooks の有効化

clone したら最初に 1 回実行する。

```
./scripts/setup-hooks.sh
```

- コミット前に秘密情報を検査する（gitleaks）
- **gitleaks が未導入のとき**は、検査できない旨を警告として表示する。導入するまで、差分に鍵やトークンが無いかを自分の目で確認してから push する
- `--no-verify` でフックを飛ばさない
