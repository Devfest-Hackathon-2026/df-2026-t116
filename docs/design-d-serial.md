# 案D 設計書（2）：連載の形・スワイプの評価・漫画アプリの画面

> 11/10 中村が決めた事を AI がまとめた。[設計書（1）](design-d-4koma.md) の 1節・2節・5節・6節のうち、ここに書いた所はこちらが正。
> **訂正（11/10 Haruki・[0005](decisions/0005-start-flow.md)）: 作品の始め方（作品名・物語の軸・絵柄・キャラ）と、それに伴う設定画・文チェック・回数の数え方はここが正。**（1）の「用意済みキャラ固定のみ」「キャラの自作はやらない」、および（1）3節のキャラ／設定画・7節の上限・チェック対象のうちここに書いた所は、ここを優先する。話（物語の軸・セリフ）は人が書き、AIは絵と、押したときだけの下書きに限る。

## 決めた事（11/10 中村）

- 作るのは**みんなで描く連載漫画**。1つの作品（物語の軸から始まる）が、話を重ねて続いていく
- **1話＝4ページ、1ページ＝4コマ**。**1人が描くのは1ページ（4コマのセリフ）**
- **ページは順に1つずつ決まる**。募集中のページはいつも1つ。みんなが候補を描き、**Tinder のようなスワイプで評価**し、一番人気がそのページに決まる → 次のページの募集が始まる
- 4ページ目が決まると**その話が完結**。次の話の1ページ目の募集が、前の話の最後から始まる
- 決まったページは変わらない。**完結した話は、漫画アプリと同じように1話目から全部無料で読める**
- 画面は LINE マンガ・ピッコマ・ジャンプ+ のような漫画アプリを手本に作り直す
- **作品を始める人が大枠を決める**（中村）: 物語の軸・絵柄・キャラ。描く人はその枠の中で1ページずつ続ける

## 決めた事（11/10 Haruki・開始フロー）

- **物語の軸**: 自由記入（1〜200字）。AI案は出さない（優先度低）
- **絵柄**: 6つの選択肢から選ぶ
- **キャラ**: **大きなパーツだけ選択**（髪型・髪色・体型・服の種類・服の色・年齢の印象・種族など、絵でわかるもの）＋**短い自由記入**（細部。反映されればよい）。完全な自由記入にはしない。理由は著作権（依拠性の入口を狭める）と独創性の両立（チーム調査 `0004-safety-cost.md` 案A）
- **例から選ぶ**: 既存の固定4体（ミカン・テツ・キナコ・ハカセ）を「例から選ぶ」として残す。パーツ選択の代わりに使える
- **作品名**: 自由記入。開始時は無くてよい（画面は「無題」）。始めた人が好きなときに付ける。AI案は後回し
- **続きを書く人**は作品のページで物語の軸を読んでから参加する
- **設定画**: 開始後にAIが作り、**始めた人が確認する**。描き直しは**1作品あたり2回まで**。確定した設定画を毎ページの参照画像に渡す
- **費用**: GCPの予算・spend capは変えない。設定画の枚数抑制・同一入力の使い回し・リトライ上限・1K固定で枚数を確保。サービス間で上限は移せない。Vertex 上限でおおよそ月140〜150枚が目安
- **実装時期**: 本設計の PR マージ後、Demo Day（11/27）まで
- **優先**: 必須＝作品名任意＋PATCH／パーツ選択キャラ＋文チェック／設定画生成＋確認（描き直し2回）。余裕＝キャラ案の下書き（パーツ＋短文向け）。後回し＝作品名のAI案。やらない＝物語の軸のAI補助・画像アップロード・完全自由記入の見た目文

## 決まり（AI が決めた細部。理由つき）

| 事 | 決めた値 | 理由 |
|---|---|---|
| 1人の候補の数 | 1つのページに1人1本（失敗・止められた時は描き直せる） | 1人で候補を埋められないように |
| スワイプ | 右＝いいね、左＝いまいち。ボタン（✕・♥）と左右キーでも同じ。1つ前に戻せる | スワイプだけだと気づかれにくい・誤操作の取り消しが要る（NN/G・WCAG 2.5.1） |
| 理由 | いいねの後に4つの理由（続きが気になる・展開が意外・キャラが良い・絵が良い）を1タップで付けられる。付けなくても次へ進む | 評価は1タップで終え、詳しい事は後から任意で（NN/G） |
| 見せない物 | 他人の候補の票数は、自分がスワイプするまで見せない。カードの順は人ごとにばらばら | 票数を見せると偏りが増す（Salganik 2006）・順番の偏りを減らす |
| 自分の候補 | 自分の候補は評価の山に出さない。自分の候補のいいね数と理由の内訳は自分にだけ見せる | 描いた人への反応 |
| ページが決まる時 | ①完成した候補が2本以上あり、最初の完成から5分たった　②完成した候補が1本だけでも30分たった　③作品を始めた人が「締めて決める」を押した（候補1本以上）、のどれか | デモでは③で進められる。放っておいても止まらない |
| 勝ち | いいねの数 → いいねの割合 → 早く描いた方 → id の順 | 同数でも必ず1本に決まる |
| 絵柄 | 自由な文ではなく6つから選ぶ（明るいカラー・少年漫画・少女漫画・劇画・ゆるかわ・モノクロ） | 自由な文だと実在の作家・作品の名前が入りやすい。全ページで同じ指示を使うので絵がそろう |
| 作品名 | 保存は空文字にしない。未設定はフィールド無し（または null）。画面だけ「無題」。0〜20字。始めた人だけ後から付け・直せる | 最初から決めさせると始めのハードルが上がる |
| キャラ | 1〜2体。①例から選ぶ（固定4体）か ②パーツ選択＋短い自由記入（名前1〜20字・自由記入0〜80字）。サーバーがパーツから見た目文を組み立てる。確定後は見た目の編集なし | 完全自由記入だと既存キャラの特徴羅列で依拠しやすい。パーツで入口を狭めつつ組み合わせで独創性を残す |
| 設定画 | 開始後に画像AIが1体1枚。始めた人が確認し、描き直しは**1作品2回まで**（全体1日120回に1枚＝1回で数える）。揃い・確認が終わるまで1ページ目は描けない。確定後はその画像を毎ページの参照に渡す。管理者は問題のある作品を非表示にできる余地を残す | 設定画を別枠にすると Vertex 上限を超えやすい |
| 文チェック | 物語の軸・キャラ名と短い自由記入・作品名（POST／PATCH）を文章AIで確かめる。不適切・実在の人・他作品名・既存キャラを想起させる文を拒む。画像指示にも「既存作品に似せない」 | 名前拒否だけでは足りない |
| AI下書き（assist） | 押したときだけ。1人1日5回（Flash・ページ生成とは別枠）。キャラ案は余裕があれば、作品名案は後回し | 無制限だと積み上がる |
| 費用の守り | GCPの予算・spend capは変えない。サービス間で上限は移せない。Vertex 上限でおおよそ月140〜150枚が目安。同一入力の使い回し・リトライ上限・1K固定で枚数を確保 | クレジット内・カード請求なしが絶対条件 |
| 生成への渡し方 | 文章AIへ: 物語の軸・絵柄・キャラの名前と見た目文・第何話の何ページ目・1つ前のセリフ。画像AIへ: **確定した設定画**・絵柄・1つ前のページ画像・指示文（セリフは人の文をそのまま） | 役割を分ける |
| 締めの処理 | 読む時・描く時・評価する時に条件を見て、満たしていればその場で決める（1つのトランザクションで） | 時計の仕組みを足さずに済む |
| 無題の見分け | ホームの棚・スワイプのカードで無題のときは、物語の軸の冒頭（約20字）か始めた人の名前を添える | 無題が並ぶと区別できない |

## 画面

下に固定のタブ: **ホーム／評価する（残りの枚数の印）／作品を始める**。色は白地に黒い文字、目立たせる色は1つ。

1. **ホーム `/`**: 大きな看板（いま一番動いている作品の表紙）→「評価待ち N枚」の帯（押すとスワイプへ）→ 横の棚「連載中」（表紙カード 2:3・作品名または無題＋軸の冒頭・「第2話 3/4」）→ 全作品の3列の表紙
2. **作品のページ `/t/[id]`**: 表紙と作品名（無題なら「無題」）・**物語の軸**・絵柄・キャラ・始めた人 → 設定画の確認／描き直し（始めた人・残り回数表示）→ 「いま募集中」の箱に「候補を評価する」「このページを描く」（設定画の確認前は描けない）→ 話の一覧 → 「1話から読む」か「続きから読む」。始めた人には「締めて決める」・「作品名を付ける／直す」
3. **読む画面 `/t/[id]/ep/[n]`**: 暗い背景。その話のページを縦に並べて読む。タップで上下メニュー。各ページの下にセリフ。最後に「第N話 おわり」と「次の話へ」
4. **評価する `/swipe`（`?theme=` 可）**: 重ねたカード。無題なら軸の冒頭を添える。✕・↶・♥。♥ の後に理由の札
5. **描く `/t/[id]/write`**: 上に物語の軸とキャラを短く出し、1つ前のページを見せる。コマ1〜4のセリフ（各30字・空欄可・1つは要る）
6. **作品を始める `/new`**: 物語の軸（1〜200字）・絵柄（6つ）・キャラ1〜2体（**例から選ぶ**または**パーツ選択＋短い自由記入**）・作品名（任意）。送ると文チェックのあと作品を作り、設定画生成→始めた人の確認へ

スワイプの作り: 素の Pointer Events と CSS。カードに `touch-action: pan-y`。幅の30%以上か速さ 0.5px/ms 超で確定。回転最大15度。離すと 0.25 秒で戻り、確定なら 0.28 秒で飛ぶ。

## サーバーの入口（形は `src/lib/apiTypes.ts`）

| 入口 | 中身 |
|---|---|
| `GET /api/themes` | `{ themes: ThemeSummary[] }` 更新の新しい順・最大50 |
| `POST /api/themes` | `{ title?, text, artStyle, characters }`（characters は例idまたは `{ name, parts, note? }`）→ 文チェックのあと作品作成・設定画生成開始（全体上限に数える）。要ログイン |
| `PATCH /api/themes/[id]` | 始めた人だけ。`{ title }`（1〜20字）。文チェックあり |
| `POST /api/themes/[id]/sheets/confirm` | 始めた人だけ。設定画を確定する → 1ページ目が描けるようになる |
| `POST /api/themes/[id]/sheets/retry` | 始めた人だけ。描き直し（1作品2回まで・全体上限に再カウント） |
| `POST /api/themes/assist` | `{ kind: "character" または "title", … }`。1人1日5回。title 時は `themeId` 必須・始めた人だけ。Demo Day 必須ではない |
| `GET /api/themes/[id]` | `ThemeDetail2`（設定画の状態・描き直し残を含む） |
| `POST /api/themes/[id]/confirm` | 始めた人だけ。票でページを決める |
| `POST /api/nodes` | 設定画未確定なら 409。他は従来どおり |
| `GET /api/deck` / `POST|PATCH|DELETE /api/votes` / `GET /api/images/[nodeId]` | 変えない（設計書（2）の既存どおり） |

データの足し算（Firestore）: `themes` に `title`（未設定可）・`artStyle`・`characters`（例idまたは parts＋note、`sheetPath`・`sheetStatus`・`sheetRetries`）・`confirmed`・`slotOpenedAt`・`updatedAt`。assist 回数は `usage/{uid}_{日付}_assist`。
